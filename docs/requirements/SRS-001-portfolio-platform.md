## 2. غرض النظام والمشكلة (System Purpose & Problem Statement)

### 2.1 غرض النظام (System Purpose)

إنشاء منصة موقع شخصي احترافية وعالية الأداء لمطور تطبيقات وأنظمة محترف. تهدف المنصة إلى استعراض الخدمات المهنية، المهارات التقنية، معرض المشاريع الهندسي، والمقالات التقنية التخصصية، مع توفير لوحة تحكم إدارية محمية لمدير نظام واحد لإدارة المحتوى والرسائل والأصول.

### 2.2 المشكلة التي يحلها النظام (Problem Statement)

- **شتات التواجد الرقمي**: غياب منصة موحدة تجمع بين استعراض المشاريع البرمجية المعقدة وكتابة المقالات التقنية الاحترافية.
- **ضعف دعم اللغة العربية وRTL**: معظم القوالب الجاهزة تعاني من مشاكل تجربة المستخدم وسوء المحاذاة في واجهات RTL.
- **بطء الأداء وتجارب 3D السيئة**: استهلاك عالي لموارد الأجهزة وتراجع تقييمات SEO بسبب الاستخدام المفرط وغير المحسن للمجسمات ثلاثية الأبعاد.
- **الاعتماد على منصات خارجية**: الحاجة لوحة تحكم إدارية خاصة تضمن الاستقلالية التامة والأمان العالي دون الاعتماد على أنظمة إدارة محتوى ثقيلة أو غير آمنة.

## 4. حدود النطاق (Scope Boundaries)

### 4.1 النطاق المعتمد للمرحلة الأولى (Phase 1 In-Scope)

1. **الصفحات العامة**:
   - الصفحة الرئيسية (Home Page) المتضمنة واجهة Hero تفاعلية مدعومة بـ 3D خفيف.
   - صفحة عن المطور (About Page).
   - صفحة الخدمات المهنية (Services Page).
   - صفحة معرض المشاريع (Projects Listing Page).
   - صفحة تفاصيل المشروع (Project Detail Page).
   - صفحة المدونة التقنية (Blog Listing Page) مع تصنيفات ووسوم.
   - صفحة تفاصيل المقال (Post Detail Page) مع دعم التظليل البرمجي (Syntax Highlighting).
   - صفحة التواصل (Contact Page) مع نموذج تواصل آمن.
   - صفحة الخطأ (404 Page).
2. **إدارة المحتوى والمسؤول**:
   - حساب إداري واحد محمي لنظام المصادقة.
   - لوحة تحكم إدارية موحدة لإدارة المقالات، المشاريع، أصول الميديا، ورسائل التواصل.
3. **الجودة والخصائص الفنية**:
   - دعم كامل وNative للغة العربية وRTL.
   - تصميم متجاوب (Responsive) متوافق مع كافة الشاشات.
   - أداء استثنائي وتوافق مع معايير SEO وWCAG 2.2 AA.
   - تجربة 3D محدودة، خفيفة، ومحسنة للأداء.

### 4.2 خارج النطاق للمرحلة الأولى (Phase 1 Explicitly Out-of-Scope)

- تعدد مدراء النظام أو أدوار المحررين (Multi-tenancy / Multiple Admins).
- اشتراكات مالية أو بوابات دفع (Payments & Subscriptions).
- تعليقات الزوار العامة على المقالات (Public Comments).
- تطبيقات الهواتف الذكية (Mobile Native Apps).
- المعمارية الموزعة (Microservices Architecture).
- التجارة الإلكترونية (E-commerce).
- الواجهة متعددة اللغات الكاملة (Full Multi-language / i18n — مؤجلة لمرحلة قادمة).
- نظام الإشعارات اللحظية المتقدم (Advanced Push Notifications).

## 5. رحلات المستخدم الرئيسية (Primary User Journeys)

### 5.1 رحلة الزائر (Visitor Journey)

1. يدخل الزائر إلى الصفحة الرئيسية ويشاهد التقديم البصري المحسن (3D Hero خفيف وسريع).
2. يستعرض الخدمات والتقنيات المستخدمة ويرتاد معرض المشاريع.
3. يصفّي المشاريع حسب التقنية (مثل: Next.js, TypeScript, PostgreSQL) ويدخل على تفاصيل مشروع معين.
4. يتصفح المدونة التقنية، يقرأ مقالاً تخصصياً، ونسخ الأكواد المظللة برمجياً.
5. ينتقل إلى صفحة التواصل، يملأ النموذج الآمن، ويستلم تأكيد نجاح الإرسال.

### 5.2 رحلة مدير النظام (Admin Journey)

1. ينتقل مدير النظام إلى مسار اللوحة المحمية `/admin/login`.
2. يدخل بيانات المصادقة المحمية بنجاح ويتم توجيهه إلى لوحة التحكم الرئيسية (`/admin`).
3. يستعرض ملخص الإحصائيات (عدد المقالات، المشاريع، والرسائل الجديدة).
4. ينشئ مقالاً تقنياً جديداً بصيغة Markdown/Rich Text ويقوم برفع صور توضيحية ونشره.
5. يستعرض رسائل الوارد من نموذج التواصل ويقوم بتحديث حالتها إلى (مقروءة / مقضية).

## 6. المتطلبات الوظيفية (Functional Requirements)

### 6.1 مصادقة إدارية (Authentication - `FR-AUTH`)

- `FR-AUTH-001`: يجب أن يوفر النظام آلية تسجيل دخول آمنة لمدير نظام واحد فقط باستخدام اسم المستخدم/البريد وكلمة المرور المشفرة.
- `FR-AUTH-002`: يجب حماية جميع مسارات اللوحة الإدارية `/admin/*` ورفض أي طلب غير مصادق عليه بإرجاع إعادة توجيه لصفحة الدخول.
- `FR-AUTH-003`: يجب إدارة الجلسة باستخدام جلسات آمنة (HTTP-only, Secure, SameSite Cookies) وتحديد وقت انقضاء تلقائي للجلسة.
- `FR-AUTH-004`: يجب حظر محاولات الدخول المتكررة الفاشلة (Rate Limiting / Account Lockout after 5 failed attempts).

### 6.2 إدارة المقالات (Technical Posts - `FR-POSTS`)

- `FR-POSTS-001`: يجب أن يتمكن الأدمن من إنشاء، تعديل، حذف، وحفظ مسودات المقالات التقنية.
- `FR-POSTS-002`: يجب أن تدعم المقالات محرر Markdown / Rich Text مع دعم إدراج الكود البرمجي والصور.
- `FR-POSTS-003`: يجب دعم تصنيف المقالات (Categories) وإضافة الوسوم (Tags) وتصفيتها بناءً عليها.
- `FR-POSTS-004`: يجب عرض المقالات المنشورة فقط للعامة في صفحة المدونة مع إمكانية البحث والتصفية.
- `FR-POSTS-005`: يجب توفير جدول محتويات ديناميكي (TOC) وتظليل الكود (Syntax Highlighting) في صفحة المقال.

### 6.3 إدارة المشاريع (Projects Showcase - `FR-PROJECTS`)

- `FR-PROJECTS-001`: يجب أن يتمكن الأدمن من إضافة وتحديث وحذف المشاريع الهندسية في المعرض.
- `FR-PROJECTS-002`: يجب أن يتضمن كل مشروع: العنوان، الوصف المختصر، الوصف التفصيلي، وسوم التقنيات المستعملة، رابط البث الحقيقي (Live Demo)، رابط المستودع (GitHub)، المعرض الصوري، وعلامة المميز (Featured).
- `FR-PROJECTS-003`: يجب توفير واجهة تصفية شبكية (Grid Filter) للمشاريع بناءً على التقنيات في صفحة المشاريع العامة.

### 6.4 إدارة الوسائط والأصول (Media Assets - `FR-MEDIA`)

- `FR-MEDIA-001`: يجب توفير مكتبة ميديا في لوحة التحكم لرفع وإدارة الصور والأصول ثلاثية الأبعاد (.glb / .gltf).
- `FR-MEDIA-002`: يجب ضغط الصور تلقائياً وتحويلها إلى صيغ حديثة (WebP / AVIF) وتوليد أحجام متعددة متجاوبة.

### 6.5 التواصل والرسائل (Contact & Messages - `FR-CONTACT`)

- `FR-CONTACT-001`: يجب توفير نموذج تواصل عام يجمع: الاسم، البريد الإلكتروني، عنوان الرسالة، ونص الرسالة.
- `FR-CONTACT-002`: يجب حماية النموذج ضد السبام باستخدام تقنيات Honeypot وحصر معدل الطلبات (Rate Limiting).
- `FR-CONTACT-003`: يجب تخزين الرسائل الواردة في قاعدة البيانات وعرضها للأدمن في لوحة التحكم مع إمكانية التحديد كمقروء/محذوف.

### 6.6 اللوحة الإدارية (Dashboard & Audit - `FR-ADMIN`)

- `FR-ADMIN-001`: يجب عرض شاشة ملخص تنفيذي تتضمن عدادات المقالات، المشاريع، الرسائل غير المقروءة، وسجل العمليات الأخيرة.
- `FR-ADMIN-002`: يجب تسجيل كافة العمليات الإدارية الحساسة (إنشاء، تعديل، حذف) في سجل تدقيق غير قابل للتعديل (Audit Log).

### 6.7 محركات البحث والتهيئة (SEO & Metadata - `FR-SEO`)

- `FR-SEO-001`: يجب توليد Dynamic OpenGraph & Twitter Card Meta Tags لكافة الصفحات والمقالات والمشاريع.
- `FR-SEO-002`: يجب توليد `sitemap.xml` و `robots.txt` تلقائياً وبشكل ديناميكي.
- `FR-SEO-003`: يجب تضمين بيانات JSON-LD المنسقة (Structured Data) لمقالات المدونة، والمشاريع، وبروفايل المطور.

## 7. المتطلبات غير الوظيفية (Non-Functional Requirements)

### 7.1 الأداء (Performance - `NFR-PERF`)

- `NFR-PERF-001`: درجة مؤشر Lighthouse يجب أن لا تقل عن **90/100** في الأداء لصفحات الجوال والسطح.
- `NFR-PERF-002`: زمن رسم أكبر عنصر محتوى (LCP) يجب أن يكون **≤ 2.5 ثانية**.
- `NFR-PERF-003`: إجمالي تغيير مظهر الصفحة (CLS) يجب أن يكون **≤ 0.1**.

### 7.2 الأمان (Security - `NFR-SEC`)

- `NFR-SEC-001`: الالتزام التام بتوصيات OWASP Top 10 لحماية التطبيق ضد تذبذب الإدخال (XSS, CSRF, SQLi).
- `NFR-SEC-002`: تطبيق ترويسات الأمان الصارمة (Strict CSP, HSTS, X-Frame-Options, X-Content-Type-Options).
- `NFR-SEC-003`: تشفير كلمات المرور باستخدام خوارزميات Authoritative حديثة (Argon2id أو Bcrypt مع Cost Factor مناسب).
- `NFR-SEC-004`: خلو كامل للمستودع من أي مفاتيح أو أسرار (Zero Hardcoded Secrets).

### 7.3 الإتاحة والتجاوب وRTL (Responsive, RTL & Accessibility - `NFR-UX`)

- `NFR-UX-001`: دعم كامل وNative لجميع واجهات RTL ومحاذاة النصوص والترتيب البصري باللغة العربية.
- `NFR-UX-002`: تصميم متجاوب سلس يعمل بكفاءة على الشاشات من 320px وحتى 4K.
- `NFR-UX-003`: التوافق الكامل مع معيار **WCAG 2.2 AA** لإتاحة الاستخدام (درجة تباين الألوان ≥ 4.5:1، دعم التنقل باللوحة، وقارئات الشاشة).

### 7.4 الحفظ التلقائي والسجلات (Backup & Audit Log - `NFR-OPS`)

- `NFR-OPS-001`: حظر تعديل سجلات التدقيق الإداري (Immutable Audit Logs).
- `NFR-OPS-002`: جاهزية معمارية النسخ الاحتياطي الدوري لقاعدة البيانات.

## 8. متطلبات التجربة ثلاثية الأبعاد (3D Requirements - `NFR-3D`)

- `NFR-3D-001`: **محدودية الاستخدام**: يقتصر استخدام العناصر ثلاثية الأبعاد على قسم Hero في الصفحة الرئيسية ومعرض تفاصيل بعض المشاريع المحددة فقط. يمنع منعا باتاً وضع 3D في الصفحات الإدارية أو صفحات المقالات.
- `NFR-3D-002`: **التحميل اللاحق (Lazy Loading)**: يجب تحميل مكتبة 3D وأصول المجسمات (.glb/.gltf) ديناميكياً وبشكل كسول (`next/dynamic` مع `ssr: false`) لعدم إعاقة تحميل الصفحة الأساسي.
- `NFR-3D-003`: **الخيار البديل (Fallback System)**: يجب توفير بديل بصري 2D محسن (صورة عالية الجودة / تدرج CSS / SVG تفاعلي) للأجهزة الضعيفة، الجوالات القديمة، أو المتصفحات التي لا تدعم WebGL.
- `NFR-3D-004`: **احترام خيارات الحركة (Reduced Motion)**: يجب تعطيل التحريك التلقائي والمجسمات عند تفعيل تفضيل `prefers-reduced-motion` لدى المستخدم.
- `NFR-3D-005`: **سلامة SEO والوصول**: يجب أن لا تعيق كائنات 3D قراءة النصوص، شجرة الإتاحة (Accessibility Tree)، أو محركات البحث.

## 10. حالات الخطأ والظروف الاستثنائية (Expected Error States)

1. **فشل الاتصال بقاعدة البيانات**:
   - عرض صفحة خطأ مخصصة 500 دون تسريب أية تفاصيل بنية تجميعية أو أسرار للنظام.
2. **محاولات الاختراق أو إدخال بيانات ضارة**:
   - رفض المدخلات بحالة HTTP 400 وتفعيل محدد المعدل (Rate Limiter) بـ HTTP 429.
3. **فشل تحميل مجسم 3D**:
   - الانتقال التلقائي الصامت للبديل البصري 2D (Graceful Degradation) دون إيقاف باقي الصفحة.
4. **محاولة الوصول لمسار غير موجود**:
   - عرض صفحة 404 متجاوبة تدعم RTL وتوفر روابط العودة للصفحة الرئيسية.

## 11. الافتراضات، المخاطر، الاعتمادات، والأسئلة المفتوحة (Assumptions, Risks, Dependencies & Open Questions)

### 11.1 الافتراضات (Assumptions)

- النشر النهائي سيكون على بيئة تدعم Node.js 20+ مع مشغل متوافق مع Next.js App Router.
- مدير نظام واحد كافٍ لكافة العمليات الإدارية في المرحلة الأولى.

### 11.2 المخاطر (Risks)

- **خطر الأداء مع 3D**: احتمالية تأثر سرعة التحميل على أجهزة الجوال ذات المواصفات المنخفضة. (تم تحييده بشرط التحميل الكسول والبديل 2D).
- **خطر السبام في نموذج التواصل**: (تم تحييده بـ Honeypot وRate-limiting).

### 11.3 الاعتمادات (Dependencies)

- حزمة Next.js 16+ وReact 19+.
- مكتبة Three.js / React Three Fiber (تُحمل كـ Lazy Module عند الحاجة).

### 11.4 الأسئلة المفتوحة (Open Questions)

- _س1: هل يفضل إضافة خدمة إرسال بريد إلكتروني تلقائي (مثل Resend/SendGrid) لإشعار الأدمن عند وصول رسالة جديدة أم الاكتفاء بعرضها في اللوحة؟_ (متروك لتوجيه COO في مرحلة ADR).
