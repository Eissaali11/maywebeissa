## 2. غرض النظام

موقع شخصي احترافي لمطور تطبيقات وأنظمة يجمع: استعراض المشاريع، المقالات التقنية، الخدمات، ولوحة تحكم إدارية محمية لمدير واحد — مع دعم كامل للغة العربية وRTL.

**المشكلة التي يحلها:** غياب منصة عربية موحدة للمطور، ضعف دعم RTL في القوالب الجاهزة، الرفع غير الآمن للوسائط، وتجارب 3D ثقيلة تضر بالأداء وSEO.

## 4. حدود النطاق

### داخل النطاق — المرحلة الأولى

- صفحات عامة: الرئيسية (Hero 3D خفيف)، عن المطور، الخدمات، المشاريع، تفاصيل المشروع، المدونة، تفاصيل المقال، التواصل.
- حالة نظام `app/not-found.tsx` عند طلب مسار/مورد غير موجود.
- مدير نظام واحد مع جلسة محمية وتوجيه تلقائي لبوابة الدخول.
- إدارة المقالات، المشاريع، الوسائط (Presigned Upload)، الرسائل.
- أرشفة المحتوى بديلاً عن الحذف النهائي (سياسة الاحتفاظ تُحدد في ADR-001).
- إعادة تنشيط الكاش (Cache Revalidation) فور النشر.
- دعم RTL وArabic، تصميم متجاوب، SEO، WCAG 2.2 AA.

### خارج النطاق

- تعدد المدراء أو المحررين، مدفوعات، تعليقات عامة، تطبيقات جوال، Microservices، تجارة إلكترونية، i18n كامل، إشعارات متقدمة.

## 5. رحلات المستخدم الرئيسية

### الزائر

1. يفتح الرئيسية ← يستعرض المشاريع ويصفيها حسب التقنية ← يقرأ مقالاً مع TOC وSyntax Highlighting ← يملأ نموذج التواصل ← يستلم تأكيد الإرسال.
2. طلب مسار غير موجود → يُوجَّه لواجهة `not-found.tsx`.

### الأدمن

1. يحاول فتح مسار محمي بلا جلسة → يُحوَّل لبوابة `/admin/login`.
2. يسجل دخوله; فشل → رسالة موحدة غير كاشفة; نجاح → جلسة محمية + توجيه للوحة.
3. ينشئ مقالاً، يحفظه مسودة، ينشره → يُسجَّل سجل تدقيق + تنشيط الكاش فوراً.
4. يرفع ميديا عبر Presigned URL مباشرة للمخزن → يؤكد الرفع → تُسجَّل بيانات الوصف في DB.
5. يؤرشف محتوى أو يضع علامة للمراجعة بدلاً من الحذف النهائي (ريثما تُعتمد سياسة الاحتفاظ).

## 6. المتطلبات الوظيفية

### FR-AUTH — المصادقة وحماية المسارات

- **FR-AUTH-001**: آلية دخول لمدير واحد مع جلسة محمية.
- **FR-AUTH-002**: توجيه تلقائي لأي طلب غير مصادق على `/admin/*` نحو `/admin/login`.
- **FR-AUTH-003**: رسالة خطأ موحدة عند فشل الدخول، لا تكشف وجود الحساب أو عدمه.
- **FR-AUTH-004**: حصر معدل المحاولات الفاشلة ومنع هجمات التخمين.
- **FR-AUTH-005**: فحص الجلسة قبل تنفيذ أي عملية تعديل إدارية.

### FR-POSTS — المقالات

- **FR-POSTS-001**: إنشاء وتعديل وأرشفة المقالات بصيغة **Markdown فقط في المرحلة الأولى** (Rich Text خارج النطاق ما لم يُعتمد صراحةً لاحقاً).
- **FR-POSTS-002**: تصنيفات (Categories) ووسوم (Tags) مع تصفية عامة.
- **FR-POSTS-003**: جدول محتويات تلقائي (TOC) وتظليل كود برمجي (Syntax Highlighting).
- **FR-POSTS-004**: سجل تدقيق عند التعديل أو النشر + تنشيط الكاش فور النشر.

### FR-PROJECTS — المشاريع

- **FR-PROJECTS-001**: إنشاء وتعديل وأرشفة المشاريع مع بيانات: عنوان، وصف، رابط معاينة، رابط مستودع، معرض صور.
- **FR-PROJECTS-002**: تصفية المشاريع العامة بوسوم التقنيات.
- **FR-PROJECTS-003**: ربط غلاف المشروع بأصول Presigned Upload.

### FR-MEDIA — الوسائط والرفع المباشر

- **FR-MEDIA-001**: رفع الملفات مباشرة من المتصفح لمخزن خارجي عبر Presigned URL قصير الأجل.
- **FR-MEDIA-002**: حظر تدفق الثنائيات عبر خادم التطبيق وتخزين الملفات في DB.
- **FR-MEDIA-003**: فحص الجلسة ونوع MIME وحجم الملف وامتداده قبل إصدار Presigned URL.
- **FR-MEDIA-004**: معالجة حالات الفشل: MIME غير مسموح، تجاوز الحجم، انتهاء صلاحية الرابط، فشل الرفع.
- **FR-MEDIA-005**: تسجيل بيانات الأصل في DB مع سجل تدقيق بعد تأكيد نجاح الرفع.

### FR-CONTACT — التواصل

- **FR-CONTACT-001**: نموذج تواصل مع حماية من السبام (Honeypot + حصر المعدل).
- **FR-CONTACT-002**: تخزين الرسائل الواردة (UNREAD) وعرضها في لوحة التحكم مع إمكانية الأرشفة (ريثما تُحدد سياسة الاحتفاظ في ADR-001).

### FR-ADMIN — اللوحة وسجلات التدقيق

- **FR-ADMIN-001**: لوحة ملخص تنفيذي (إحصائيات + آخر العمليات).
- **FR-ADMIN-002**: سجل تدقيق ذري وغير قابل للتعديل لكل عملية إدارية.

### FR-SEO — محركات البحث

- **FR-SEO-001**: توليد OpenGraph وMeta Tags ديناميكياً لكل صفحة ومقال ومشروع.
- **FR-SEO-002**: توليد `sitemap.xml` و`robots.txt` وبيانات JSON-LD منسقة تلقائياً.

## 7. المتطلبات غير الوظيفية

### NFR-PERF — الأداء

- **NFR-PERF-001**: درجة Lighthouse ≥ 90/100 للأداء على الجوال والسطح.
- **NFR-PERF-002**: LCP ≤ 2.5 ثانية.
- **NFR-PERF-003**: CLS ≤ 0.1.

### NFR-SEC — الأمان

- **NFR-SEC-001**: الامتثال لـ OWASP Top 10 ضد XSS, CSRF, SQLi.
- **NFR-SEC-002**: ترويسات أمان صارمة (CSP, HSTS, X-Frame-Options, X-Content-Type-Options) — الآلية التقنية تُحدد في ADR-001.
- **NFR-SEC-003**: تشفير كلمات المرور بخوارزمية آمنة ومعتمدة — الخوارزمية تُحدد في ADR-001.
- **NFR-SEC-004**: مستودع خالٍ تماماً من أسرار أو مفاتيح مضمنة (Zero Hardcoded Secrets).

### NFR-UX — التجاوب وRTL والإتاحة

- **NFR-UX-001**: دعم RTL وArabic Native في كل الواجهات.
- **NFR-UX-002**: تصميم متجاوب من 320px حتى 4K.
- **NFR-UX-003**: توافق كامل مع WCAG 2.2 AA (تباين ≥ 4.5:1، تنقل بالوحة، قارئات الشاشة).

### NFR-OPS — التشغيل والسجلات

- **NFR-OPS-001**: سجلات التدقيق غير قابلة للتعديل (Immutable).
- **NFR-OPS-002**: معمارية قابلة للنسخ الاحتياطي الدوري لـ DB.

### NFR-3D — تجربة ثلاثية الأبعاد

- **NFR-3D-001**: 3D محدود بقسم Hero الرئيسي وبعض تفاصيل المشاريع فقط.
- **NFR-3D-002**: تحميل كسول للأصول ثلاثية الأبعاد لا يعيق رندر الصفحة الأساسي.
- **NFR-3D-003**: بديل بصري 2D عند عدم دعم WebGL أو الأجهزة الضعيفة.
- **NFR-3D-004**: تعطيل الحركة تلقائياً عند تفعيل `prefers-reduced-motion`.
- **NFR-3D-005**: عناصر 3D لا تعيق النصوص أو شجرة الإتاحة أو محركات البحث.

## 8. حالات الخطأ

1. **فشل Presigned Upload**: MIME/حجم غير مسموح → 400/403؛ انتهاء صلاحية الرابط → تنبيه مع إمكانية إعادة المحاولة.
2. **فشل DB**: صفحة خطأ 500 مخصصة بلا كشف لتفاصيل البنية.
3. **إدخال ضار**: رفض 400/429 مع Rate Limiting.
4. **فشل تحميل 3D**: انتقال صامت للبديل 2D.
5. **مسار غير موجود**: تفعيل `not-found.tsx` مع روابط للرئيسية.

## 9. الافتراضات والمخاطر والاعتمادات

**الافتراضات:** Node.js 20+ وNext.js App Router؛ مخزن أصول متوافق S3؛ مدير نظام واحد في المرحلة الأولى.

**المخاطر:** أداء 3D على الجوال الضعيف (مُخفَّف بالتحميل الكسول والبديل 2D)؛ سبام نموذج التواصل (مُخفَّف بـ Honeypot + Rate Limiting).

**الاعتمادات:** Next.js 16+ · React 19+ · مخزن متوافق S3 (Cloudflare R2 أو غيره — يُحدد في ADR-001).
